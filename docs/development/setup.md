# Development Setup

## 1. Purpose

Get a new contributor from a clean checkout to a running local environment.

## 2. Context

Phase 0 establishes the structure and configuration templates this document
refers to; the actual runnable backend/frontend code is built in later
phases. This document will be updated as each phase lands real code — right
now it describes the target setup, with notes on what's not implemented
yet.

## 3. Current decision — setup steps

### Prerequisites

```
- Docker + Docker Compose
- Python 3.11+ (for running ML/backend code outside Docker, e.g. notebooks)
- Node.js 20+ (for frontend development outside Docker)
- Git
```

### Steps

```bash
# 1. Clone and enter the repo
git clone <repo-url> recoverai
cd recoverai

# 2. Configure environment
cp .env.example .env
# edit .env with real values (DB password, OpenAI key, Razorpay test keys, etc.)

# 3. (Once backend/frontend code exists) start the full stack
docker compose up --build

# 4. Backend will be available at:
http://localhost:8000
# API docs (auto-generated by FastAPI) at:
http://localhost:8000/docs

# 5. Frontend will be available at:
http://localhost:3000
```

### Running ML/simulation code standalone (without Docker)

```bash
cd ml  # or simulation/
python -m venv .venv
source .venv/bin/activate   # or .venv\Scripts\activate on Windows
pip install -r requirements.txt   # created when Phase 2/3 lands
```

## 4. Alternatives considered

Considered requiring only Docker (no local Python/Node needed at all).
Rejected as the *only* documented path — ML experimentation
(`ml/experiments/`) is far more convenient with a local Python environment
and notebook tooling than through a container rebuild cycle; Docker remains
the source of truth for the demo-ready full stack.

## 5. Why this option

Matches the instruction to keep local development simple and reproducible,
while acknowledging that ML iteration work benefits from a lighter-weight
local loop than the full containerized stack.

## 7. Implementation implications

- `backend/requirements.txt`, `ml/requirements.txt`, and
  `frontend/package.json` will be created as each phase introduces real
  dependencies — Phase 0 does not pin dependency versions since no code
  exists yet to depend on them.
- `infrastructure/docker/backend.Dockerfile` and `frontend.Dockerfile`
  (referenced by `docker-compose.yml`) are created in Phase 6/11
  respectively, alongside the code they containerize.
